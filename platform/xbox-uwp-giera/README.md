# Giera UWP host

Packaged Windows/Xbox app that boots the Giera web build inside a WebView2 control, with a native splash.

## Why WebView2, not the classic XAML `WebView`

The classic `Windows.UI.Xaml.Controls.WebView` is EdgeHTML: no WebGL2, no ES2022. Giera is three.js r186 on WebGL2 with a `es2022` build target, so it cannot run there — the control paints a blank page. WinUI 2.8 ships `Microsoft.UI.Xaml.Controls.WebView2` for UWP (Chromium), which is the engine Giera needs. Microsoft's WinUI 2 WebView2 getting-started article lists Windows and Xbox as supported platforms.

## Splash

Two layers:

1. `Package.appxmanifest` → `uap:SplashScreen` (`Assets/SplashScreen.png`, background `#0b1020`) drawn by the OS before any app code runs.
2. `MainPage.xaml` → `SplashLayer`: `Assets/SplashLogo.png` + indeterminate progress bar + status text. It hides when the web splash video or fallback card becomes visible, with a 45 s timeout fallback and a hard error message when the WebView2 runtime or navigation fails.

The native layer plays no video. The web app owns the splash animation (`src/client/startup/splash-video.ts`), so only the WebView2 process decodes a video.

## Microphone

WebView2 default-denies page media capture, so `getUserMedia` and the Web Speech API inside the app failed with `NotAllowedError`. `MainPage` handles `CoreWebView2.PermissionRequested` and answers `Allow` for the `Microphone` kind only (every other kind is denied); `Package.appxmanifest` declares the `microphone` device capability. Each decision is written to `boot-log.txt`.

## Boot log

`MainPage` writes `boot-log.txt` to the app's `LocalFolder`: engine version, WebGL2 support, `boot-ready`, plus state snapshots (ready, playing music, audio context state, fps, launch menu present). Read it on a console with `./deploy-xbox.sh log`.

Chromium autoplay is relaxed via `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--autoplay-policy=no-user-gesture-required`, so the menu music starts without a click.

## Build

```bash
bun platform/xbox-uwp-giera/sync-web.ts     # vite build -> Assets/www
# on a Windows box with Visual Studio + UWP workload:
powershell -ExecutionPolicy Bypass -File platform\xbox-uwp-giera\build-giera.ps1
```

`build-giera.ps1` creates the self-signed `Giera.Uwp_TemporaryKey.pfx` (CN=Giera Uwp, password `giera-dev-pass`) on first run, then builds Release x64 and prints the `.msix` path.

Install on a desktop: trust the pfx, then `Add-AppxPackage` the printed `.msix`. Install on an Xbox in Developer Mode: `CONSOLE=… PORTAL_USER=… PORTAL_PASS=… ./deploy-xbox.sh install`.

## Assets

`Assets/www` is generated (`sync-web.ts`) and git-ignored. `Assets/*.png` tiles and the splash are generated by `python3 tools/make-assets.py` and committed.

The WebView loads the public game at `https://giera.tail5d39b4.ts.net/`. Change `StartUrl` in `MainPage.xaml.cs` to use another host.
